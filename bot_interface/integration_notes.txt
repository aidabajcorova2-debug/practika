Технические заметки по интеграции модулей (подводные камни)

Файл со шпаргалкой по нюансам стыковки бота, базы данных и парсера. Написано для того, кто собирает всё воедино, чтобы сэкономить время на отладке.

1. Конфликт ID (Telegram ID vs DB Row ID)
* В чём нюанс: Методы БД get_assignments и get_assignments_soon принимают на вход целочисленный внутренний id из таблицы users, а не строковый Telegram-идентификатор (user_id).
* Как решено в max_bot.py: Бот сначала запрашивает запись пользователя через get_user(telegram_id), забирает оттуда числовой ключ ['id'] и уже его передает в функции выборки заданий.

2. Нюанс с INSERT OR IGNORE при привязке ЛК
* В чём нюанс: Метод БД add_user спроектирован с логикой INSERT OR IGNORE. Если пользователь сначала нажал /start (создалась запись без логина/пароля), то при попытке позже привязать ЛК вызов add_user(user_id, login, password) просто проигнорируется базой, и данные авторизации не сохранятся.
* Как решено в max_bot.py: При вводе данных «логин:пароль» бот принудительно обновляет логин и пароль в БД через команду UPDATE, используя прямое подключение db.get_connection().

3. Различие в структурах данных (Парсер -> БД)
* В чём нюанс: Парсер возвращает плоский список словарей, а метод БД sync_assignments ожидает вложенную структуру, сгруппированную по дисциплинам. Кроме того, для работы sync_assignments нужен уникальный source_id задания.
* Как решено в max_bot.py: В коде бота прописан конвертер, который группирует плоские данные парсера по предметам, назначает в качестве source_id номер задания из ЛК и приводит даты к единому стандарту 'YYYY-MM-DD HH:MM:SS' для корректной фильтрации.

Коротко по запуску, если забылось:
1. Ставим библиотеки: pip install aiogram requests beautifulsoup4
2. Прописываем токен в max_bot.py (переменная BOT_TOKEN).
3. Сначала запускаем python database.py (создаст БД), затем python max_bot.py.
